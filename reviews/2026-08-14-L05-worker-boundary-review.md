## Scope reviewed

- Source-first multi-queue routing and independent delivery plans.
- Delivery lease SQL and worker-only database adapters.
- Strict Cloud Tasks command envelope, enqueue idempotency and Google client mapping.
- Private OIDC handler boundary, claim/publish/complete ordering and overlay wake-up behaviour.
- Executable worker bootstrap and durable replay publisher semantics.

## Evidence

- `go test ./...` passes for auth, handler, routing, store and tasks packages.
- Disposable PostgreSQL 16 harness passes through migration 0030, including claim/retry/release, publication-marker suppression, worker-only wake-up, L31/L32 snapshot persistence, browser acknowledgement and queue pause/replay protection.
- The same harness now persists one captured payment into two queue deliveries and advances only one; the second remains ready and independently claimable.
- Google Cloud Tasks adapter uses the official `cloud.google.com/go/cloudtasks/apiv2` client and maps OIDC token generation to the configured service account; no credentials were used in tests.
- Worker `db.Open` missing-DSN test passes; no live DSN or production database was used.
- Worker command and durable replay publisher compile and pass package tests; no live Cloud Tasks queue, OIDC token, DSN or production database was used.
- Worker runtime lease-token test now proves UUID v4 formatting before the token reaches the PostgreSQL `uuid` SQL parameters; `go vet ./...` and `go test ./...` pass.
- The disposable SQL harness now proves a mismatched event identity cannot claim a delivery and that the correct command remains claimable afterward (`L05-12`).
- The disposable SQL harness proves ready delivery listing, and Go tests prove pump identity mapping, stable command idempotency and retryable no-mutation enqueue failure (`L05-13`).
- The same harness edits one queue binding after acceptance and proves the persisted delivery priority/override snapshots remain unchanged for dispatch (`L05-14`).
- Go handler tests prove the private pump rejects unauthenticated calls, returns retryable failure on enqueue error and returns a bounded success summary when the scan completes (`L05-20`).
- Go command tests prove an unsupported action is rejected before any delivery claim (`L05-17`).
- The durable replay publisher test proves no pre-completion notification is emitted (`L05-18`); the handler remains the only post-completion wake-up owner.
- The disposable PostgreSQL harness proves the outbox projection remains pending after one queue completes and becomes completed only after the second queue completes (`L05-19`).
- Migration `0020` and the same harness prove two deliveries of one payment expose distinct frozen `style` overrides to overlay replay after the source bindings are edited.
- Go handler/store tests prove successful publication calls the lease release boundary, not terminal completion; the disposable SQL harness proves a released delivery is ready with no lease, remains independently reclaimable, and only the overlay acknowledgement makes it terminal.
- The new worker operations runbook defines task enqueue failure, worker crash/timeout, dead-letter, overlay disconnect/notification outage, manual replay, monitoring and rollback without a destructive backlog-clear path.
- `docker build --file Dockerfile --tag bsa-alert-worker:local .` passes for the service-local multi-stage image. The final image is distroless/non-root and contains only the static worker binary; this verifies packaging, not Cloud Run probes, IAM, Cloud Tasks queue/OIDC, overlay delivery or production capacity.
- Race-enabled local verification (`go test -race ./...`) passes for all worker packages. This strengthens local concurrency evidence but does not close live queue, overlay, capacity, fault-injection or independent-review gates.
- The SQL harness proves a released/published delivery is not returned by a later ready pump scan, while the same delivery remains visible to the overlay replay path until cursor acknowledgement. No live pump, offline-overlay or operator replay environment was used.

## Decision

The routing, lease, enqueue, handler, executable bootstrap, durable replay publisher and operator recovery-contract slices are acceptable implementation slices. They do not authorize production dispatch, live queue creation, overlay capacity claims, or closure of L05 until staging and independent-review evidence exists.
