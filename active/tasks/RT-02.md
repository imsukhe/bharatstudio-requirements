## Owner decision — 2026-09-16 — admission ceiling values

**Asked and answered by the owner:** *what per-instance and per-channel overlay subscriber
ceilings should ship as defaults, or do they stay unset until ENV-08 load evidence exists?*

**Decision: they stay unset.** `OVERLAY_MAX_INSTANCE_SUBSCRIBERS` and
`OVERLAY_MAX_CHANNEL_SUBSCRIBERS` ship with no default value. Admission is then bounded
only by the platform's own Cloud Run request-concurrency cap, which is the behaviour that
existed before this task; the mechanism, its retryable `503 overlay_admission_limited`
rejection and its slot-release path are fully built and locally tested, so setting a value
later is a configuration change and not a code change.

**Why there is no number here.** No approved authority states a per-instance or
per-channel overlay subscriber ceiling. §19.0 states only the 2,000-concurrent-overlay
design target and the Cloud Run 800-request cap, and neither yields a ceiling by
arithmetic. `governance/AGENTS.md` forbids inventing deployment values, and a guessed
ceiling is worse than none: too low it rejects real creators' overlays, too high it is
decorative.

**What would settle it:** `active/tasks/ENV-08.md` — the target-concurrency staged run at
2,000 concurrent overlays. ENV-08 is currently **Blocked** (no staging environment), so
this value is blocked behind it and nothing else in RT-02 is.
